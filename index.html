URL structure, domain names, what a server is, and what a browser does


URL structure

  1. Protocol: https:// (secure) http:// (not secure)
  2. Subdomain: www
  3. Domain: example.com
  4. Path: /example/example

Domain names

SLD(example) TLD(.com) then DNS


Servers

basically a storage shed for computers


Browsers

it takes the url and asks the server for it, then translates it to what you see

client and server demo

The browser seperates the URL into the protocol, domain, and path

The browser checks its own cache for a matching IP address

The os checks the local hosts file for any manual redirects

The router and ISPs DNS resolver check their caches next

The DNS resolver asks external servers to translate the domain into an IP address.

The browser makes a TCP connection with the IP address

The client and server do TLS to secure the connection

The browser sends an HTTP get request for the specific webpage resources

The servers load balancer receives the request and sends it to an available server

The web server processes the request and takes dynamic data from the database

The server makes and sends an HTTP response with the HTML file

The browser parses the HTML to build the document object model tree

The browser finds and requests things like CSS, images, and JavaScript

The browser runs the JS files to add dynamic interactivity to the page

The layout engine puts the pixels onto your display screen
